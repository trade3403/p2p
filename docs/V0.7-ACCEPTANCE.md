# V0.7 Acceptance Checklist — LAN P2P Direct + VPS Fallback

## Implemented in source (subject to CI)

- [x] Windows LAN listener with explicit owner opt-in, TCP 43821, private IPv4 peer allowlist.
- [x] AES-256-GCM authenticated LAN HELLO type 6 and READY type 7 before any capture/control is streamed.
- [x] Shared Rust host session pump for WSS relay and local WebSocket.
- [x] Android LAN literal-RFC1918 IPv4 validation, direct-first connection, 4-second proof timeout and relay fallback.
- [x] No VPS bearer token in LAN direct request; WSS for all public relay connections.
- [x] Direct-only mode possible; wrong/missing token can still work on explicitly enabled private LAN.
- [x] Windows loopback WebSocket+AES proof unit/integration tests; Android LAN endpoint validation unit tests.
- [x] Existing DPAPI/Android Keystore trust, JPEG/H.264, input and clipboard controls retained.
- [x] Updated V0.7 CI with ZIP/APK artifact hashes.

- [ ] Windows cargo test and cargo build --release successful.
- [ ] Windows LAN encrypted handshake loopback integration test passes.
- [ ] Android testDebugUnitTest (including LanEndpointTest) and assembleDebug pass.
- [ ] Go relay go test -race and Docker image build pass.
- [ ] Windows EXE, Android APK and SHA-256 files exist from same tested commit.
- [ ] No secrets embedded in repository or build logs.

## Manual acceptance (pending a Windows PC, Android device and optionally VPS)

- [ ] Explicitly enable LAN on Windows Private profile only. Stop prevents all new connections.
- [ ] Windows Private IPv4 is reachable from Android same-Wi-Fi; AES proof completes and screen displays.
- [ ] Wrong AES session key is rejected before any screen frame is sent.
- [ ] Public addresses, DNS hostnames and malformed IPv4 are rejected as direct endpoints.
- [ ] No VPS bearer token transits LAN; no plaintext screen/clipboard packets.
- [ ] Host LAN port TCP 43821 is NOT reachable from an outside Public network.
- [ ] With VPS ready, block LAN port and verify automatic WSS fallback.
- [ ] Android on 5G/outside LAN uses VPS fallback; do not claim NAT traversal.
- [ ] Toggle Windows remote input permission OFF and verify Android cannot control the computer.
- [ ] Verify JPEG/H.264 switching, screen changes, latency and queue counters on direct/relay links.
- [ ] Test multiple networks (router client isolation, Windows firewall, 5G, VPN) and 8-hour soak.
- [ ] Review globally enabled Android cleartext policy and replace it with strictly scoped authenticated TLS/QUIC transport before commercial release.

## Explicitly not delivered

- ICE/STUN/TURN NAT hole-punching, peer discovery across the Internet, seamless in-session transport migration with zero dropped frames.
- Video GPU hardware encoding, lock-screen/UAC control, independent per-device identity, production signed installers.
- VPS deployment and real device testing.

# V0.2 native remote desktop acceptance checklist

## Implemented in source

- [x] Windows Rust/Iced UI (server, relay token, session secret, status, control consent)
- [x] Local Rust screenshot JPEG frame generator / Windows desktop pointer input
- [x] Android Kotlin Compose UI, encrypted JPEG viewing, touch/drag and text commands
- [x] Go server one-host/one-viewer forwarding room with bearer token authentication
- [x] AES-256-GCM application-layer encryption on Rust and Android
- [x] Docker Compose + Caddy for TLS and safe internal relay exposure
- [x] GitHub Actions builds all three components and stores checksums (subject to CI logs)

## Must pass before merging/releasing

- [ ] CI: Windows EXE compiles with Rust stable / cargo test
- [ ] CI: Android APK builds successfully / Android manifest sanity
- [ ] CI: Go server tests and Docker image build
- [ ] Windows 11: starts, stops, restarts without leaking sessions
- [ ] Android: screen is readable and touch coordinates map accurately
- [ ] Mobile 5G → home Windows over VPS WSS; no static home IP/port forward
- [ ] E2E encryption: wrong session secret never shows picture, never controls host
- [ ] Control toggle off: no remote inputs; toggle on only with user consent
- [ ] Network loss and reconnection tested on both platforms
- [ ] Session disconnect, computer lock, UAC documented/handled
- [ ] Source and transitive dependency license/SBOM audit before commercial publication

## Known limitations

- JPEG frames ~6FPS, not hardware H.264; dedicated codec optimization is a future milestone.
- No automatic reconnection yet: disconnect and reconnect manually.
- VPS forwarding adds bandwidth cost and latency; no P2P bypass in V0.2.
- No Windows startup service or access to the secure desktop.
- Security hardening still needed: device-specific relay token enrollment, replay protection, per-IP rate limits, login and session audit.
- Local project tests and cloud CI cannot replace actual Windows/Android network testing.

## Deployment assumptions

- Domain DNS points to VPS; ports 80 and 443 allowed.
- An actual VPS with Docker installed is required; no server credentials are stored in GitHub.
- `deploy/.env` is not tracked by Git.
- Public server must be TLS-terminated by Caddy and isolated Docker network; do not publish Go relay port 8080.

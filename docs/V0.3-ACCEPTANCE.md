# V0.3 Functional and Security Acceptance

## Implemented in this phase (subject to CI verification)

- [x] Windows outbound relay auto-reconnect with bounded 1–30 s backoff and explicit stop.
- [x] Windows validates and persists WSS/HTTPS relay address only (never the bearer token or session secret).
- [x] Android outbound relay auto-reconnect after transport failure and manual cancellation.
- [x] Android session watchdog: reconnect on a >20 s stall after frames had been received.
- [x] Android saves only nonsecret WSS address locally.
- [x] Authenticated packet kind (AES-256-GCM AAD) on Windows and Android.
- [x] Additional Go auth/room input tests and Rust/Android retry-policy tests.
- [x] GitHub Actions V0.3 Windows EXE, Android APK, Go relay smoke build and tests (confirm logs before marking CI accepted).

## Cloud CI acceptance (must be observed, not assumed)

- [ ] Rust: `cargo test` and `cargo build --release` pass on Windows.
- [ ] Android: `testDebugUnitTest` and `assembleDebug` pass on Ubuntu runner.
- [ ] Go: `go test -race -count=1 ./...` passes; Docker relay image builds.
- [ ] Both EXE ZIP and APK artifacts exist, include SHA-256, and match the same commit.
- [ ] No credentials or signing keys appear in repository or job logs.

## Real-world acceptance (pending owner-provided VPS and devices)

- [ ] Deploy `deploy/compose.yml` on an authorized VPS behind HTTPS with a trusted certificate.
- [ ] `https://YOUR_DOMAIN/healthz` returns HTTP 200.
- [ ] Windows 10/11 PC connects outbound to VPS without public IP or port forwarding.
- [ ] Android on 5G connects to Windows through VPS; first frame appears and remote input works after consent.
- [ ] Wrong session secret never renders video and never sends accepted input.
- [ ] Wrong relay token returns 401/403; clients stop retrying.
- [ ] Temporarily block VPS/network for 30–60 s; both clients reconnect without user re-entry.
- [ ] Toggle Windows permission off; all remote input remains disabled.
- [ ] Stop Windows service and Android session; no surprise background reconnect.
- [ ] Run 8-hour soak test, log memory, frame rate, bandwidth and reconnect attempts.
- [ ] Validate phone rotation, 5G↔Wi-Fi switch, and normal Windows display scaling.
- [ ] Check operating-system restrictions for UAC, secure desktop and lock-screen behavior.

## Security boundaries

- Permission and visible connection indicators are required.
- Relay bearer token authenticates a connection to the *relay*, not a specific device/account.
- 32-byte random session key determines room and end-to-end encryption. Treat it as a password.
- AEAD type authentication in V0.3 **breaks wire interoperability with V0.2**.
- Session keys are not stored. Relay URL only is persisted.
- Self-hosted relay is a prototype: add rate limiting, key rotation, enrollment, independent security review and service isolation before commercial deployment.
- Do not expose port 8080 to the Internet.
- No attempt to bypass OS consent or privilege boundaries.

## Not yet implemented in V0.3

H.264/MediaCodec end-to-end video, QR provisioning with secure enrollment, signed release builds, audio, multi-display, clipboard/file transfer, dedicated Windows background service, and unattended login. These require separate implementation and testing.

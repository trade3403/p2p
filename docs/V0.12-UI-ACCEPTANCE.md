# P2P Remote V0.12 — navigation and visual refresh

## Goal

Make the existing V0.11 remote-control client simpler to use, using a familiar device-centric interface pattern common in remote assistance tools. **Use original P2P branding and colors; do not reproduce Sunlogin's assets, logos or exact visual design.**

## Windows (Rust/Iced)

- Replace the long single-page stack of all configuration cards with a persistent sidebar.
- **我的设备:** start/stop host, show relay endpoint, share the existing session key, see connection status and saved trusted pairing.
- **远程控制:** remote Windows Viewer, mouse/keyboard/scroll, monitor switches, clipboard.
- **安全与画质:** mouse/clipboard permission flags, JPEG/H.264 preference, FPS, LAN fallback.
- **网络诊断:** STUN and UDP probe/preview controls.
- Update surface, contrast, spacing, hierarchy and readable Chinese text.
- Keep explicit user permission gates; don't silently enable remote input, clipboard, autostart or UDP.
- No new device/account feature is implied by sidebar labels. Existing pairing is key-based.

## Android (Jetpack Compose)

- Top status plus 3 tabs: **连接设备**, **远程画面**, **更多设置**.
- Pairing and connect controls are separate from the large touch/remote video area.
- Clipboard actions and security notices remain available in More.
- Preserve encrypted shared session key flow, trusted storage and explicit connect/disconnect behavior.

## Safety and compatibility gates

- Keep `wss://p2ptest.aikissgo.com` as the V0.12 development default; saved user relay preferences may override it.
- Preserve existing WSS message formats, Relay token handling, end-to-end AES-GCM, Windows permission switches, LAN/UDP optional paths, and Android gesture mapping.
- No new registration, device discovery, remote reboot, unattended access, files, or multi-device control is claimed.
- CI artifacts must be named V0.12, be generated from one successful workflow run and pass Windows Rust tests, Android JVM tests, and Ubuntu Go Relay tests.

## Manual visual acceptance checklist

- Windows default window (1180×780) has navigation visible, correct Chinese glyph rendering and no overlapping buttons.
- Windows click each navigation item: hidden sections are accessible and the connection state remains unchanged.
- Windows Viewer remains operable with reduced video display width; larger monitors and high DPI should be checked separately.
- Android at narrow phone widths (~360dp), tabs remain legible; no horizontal scrolling required.
- Android change tabs during a session; can return to remote canvas and continue controlling host.
- Windows/Android use the same staging Relay token and session key; validate actual WSS connection against the staging domain.
- Existing V0.11 behavior remains available, including manual permission revocation and clipboard opt-in.

**Limitations:** passing CI only confirms compilation and automated tests. Manual screenshot review, DPI testing and cross-device latency have not yet been performed.

# V0.21 性能开发

基线: V0.20 b96251dff870990cec763d9c6647abcc614a8ccd，正式 UI 公网验收成功。保留 V0.20、V0.19、main。服务器继续使用 p2ptest.aikissgo.com，不部署新 Relay。

第一阶段：正式 Windows Flutter Host 协商真实 Annex-B AVC，经原有 AES-GCM/WSS 传输；无解码 Surface 的原生 JPEG E2E 和旧 Windows Viewer 保持 JPEG。Android Surface MediaCodec 优先选实际硬件解码器，显示真实 codec 名和硬件分类，失败请求 JPEG 回退。编码器当前是 OpenH264 软件，不是硬件。自适应策略按实际渲染 FPS、RTT、解码丢包反馈调整 0.4–4 Mbps、10–30 FPS；编码参数调整和丢帧后重新生成 IDR，解码丢帧后等待 IDR。目标值不是实测。横屏全屏保留真实触摸、输入、断开、退出恢复方向。

测试：独立 V0.21 原生公网 JPEG E2E 保留原测试；正式安装版双端 UI 公网验收保留原操作断言、两端实际 OS 录屏，增加横屏与持续 AVC 输出、实际 FPS/码率/RTT/codec 分类报告。CI 模拟器可能仅支持软件解码，必须如实记录。文本 UI 到 Host 回执时间包含 UI 自动化和协调通信，不能当作端到端画面延迟。

未完成：Windows Media Foundation/D3D11 硬件编码器、真实硬件设备 CI 验收、DXGI 高效采集、可复现实测弱网阶跃、严格 glass-to-glass 延迟测量及 30fps/150ms 目标验证。当前不宣称已实现硬件编码或已达到性能目标。禁止使用 MP4 录像编码格式充当实时 AVC 证据。

## 第二阶段：Windows MF 硬件编码后端

新增硬件专用异步 Media Foundation MFT 枚举、NV12 输入、低延迟配置、真实 Annex-B AVC 输出校验；无法启动或编码失败则在当前会话回退到 OpenH264。只有成功生成符合要求的访问单元才报告 Media Foundation hardware，枚举成功不等于硬件验收通过。普通 CI 无 GPU 时软件回退可通过兼容测试，不能据此宣称硬件通过。CPU NV12 staging 当前不是 D3D11/DXGI 零拷贝。下一步须在真实支持硬件 MFT 的 Windows GPU 设备验证实际编码器输出、连续渲染和回退，并测量采集/编码/显示耗时。


## 第三阶段 A：DXGI 持久采集与分段计时

Windows AVC 采集工作线程按显示器物理位置匹配 DXGI output，复用 D3D11 device、桌面 duplication 和 staging texture；正常桌面条件下读取真实 BGRA，转为 RGBA。无新 surface 时复用上一帧（单独计数），设备丢失、旋转、不可用时回退既有 screenshots 采集。非 Default 输入桌面或 DXGI 报告受保护内容时拒绝当前帧，不发送缓存内容。JPEG 兼容路径仍使用原采集库。DXGI 不是零拷贝：当前仍有 CPU readback、RGBA/NV12 转换，独立鼠标指针合成及旋转输出专用 DXGI 处理尚未实现。Android 诊断与正式 UI 测试新增真实后端名称、采集阶段均值、缩放/编码阶段均值、加密与 socket send 均值（微秒）、新采集/复用/编码累计帧数；这些是当前会话累计样本，不是 p95、网络单程延迟或 glass-to-glass。必须以实际报告区分 DXGI 与回退，且在真实 GPU 验证。30 FPS/150 ms 未验收。


## 第三阶段 B：静止桌面缓存优化

基于 run 45407116744 的实际第二次性能样本：DXGI，12.192684 FPS，RTT 311 ms，采集平均 7512 us，缩放/编码 48691 us，发送 143 us；fresh=88，reused=989，encoded=1077。软件编码和模拟器软件解码，不是 GPU 硬件加速。此次仅当同一 DXGI duplication 明确无更新时复用缩放 RGBA 和 YUV/NV12；切换显示器、模式、采集回退、错误或非交互桌面时清空缓存，编码 GOP 重置仍保留。正式 CI 新增 resize_cache_hits、yuv_cache_hits 计数，检查实际缓存使用。缓存不等于 GPU 零拷贝，物理 GPU 路径尚待实现及实机验收。


## 第三阶段 C：真实点击到可见结果的测试

正式 Windows Notepad 已验证远程文字输入后，再由 Android 真实 UI 点击 Windows 最大化和还原按钮。Windows 通过 UIA 或只读 WM_GETTITLEBARINFOEX 定位真实按钮，用 IsZoomed 与窗口矩形独立确认状态。Android 复用真实录屏采样，比较实际前后桌面截图的低分辨率指纹，仅比较具有真实变化的区域。每次使用同一个 Android 单调时钟记录从 ADB 触摸派发到第一个匹配截图采集完成的耗时，同时记录 ADB 耗时、截图耗时和采样间隔。测试不注入伪造视频，不使用跨设备时间同步、不使用回执时间当画面延迟。由于截图采样速度有限，这只是带 ADB/截图开销的视觉反馈上界样本，不能等同于精确 glass-to-glass、input-to-photon 或证明 150 ms 达标。两次真实操作样本不计算 p95。所有原有功能/性能验证和两端录屏仍保留。

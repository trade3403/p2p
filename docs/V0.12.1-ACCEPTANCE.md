# P2P Remote V0.12.1 — UI and remote input hardening

## Source branch

`feature/v0.12.1-ui-remote-polish`, based on V0.12. This is a **test release**, not V1.0.

## Delivered in source

### Windows Rust/Iced
- Fixed a V0.12 mouse mapping regression: the Viewer rendered a 660×371 viewport while normalizing pointer events with stale 800×450 dimensions, causing remote cursor offset.
- The Viewer now uses the **same** current viewport dimensions for image layout and pointer normalization.
- Added compact (560×315), standard (700×394), and large (840×473) display choices. Settings affect only image size, not host resolution.
- Remote clicks on letterbox bars are ignored by the existing geometry helper. Hiding the remote page or disconnecting attempts to release a currently held mouse button.
- Improved remote image empty-state, online status text and action enablement.

### Android Kotlin/Compose
- Moved connection, remote video and settings into persistent Material 3 bottom navigation.
- Added a direct 'enter remote screen' action from the connected-device page.
- Folded LAN/STUN diagnostics into an advanced section to reduce first-run complexity, without deleting controls.
- Separated viewport-to-remote touch conversion into `RemoteGeometry`. Black bars do not generate remote down/move events. New unit tests cover 16:9, 4:3, letterboxing and invalid viewports.
- Slightly reduced video canvas height to leave room for touch controls on small phones.

### Security and compatibility
- Retained explicit Windows host mouse/clipboard permission switches, E2E encryption and trusted pairing.
- No new background/autostart behavior or privilege escalation.
- Uses `wss://p2ptest.aikissgo.com` as the first-run development default, subject to existing saved preferences.
- No change to the Go Relay protocol, production domain configuration, user credentials or Nginx on the VPS.

## Known limitations

Windows Viewer remains JPEG-over-WSS and not yet full-screen. GPU encoding, file transfer, peer discovery, and production-grade P2P ICE/TURN are out of scope. Larger viewer preset may overflow narrow Windows windows; it is intended for normal desktop widths and must be tested before further UI refinements.

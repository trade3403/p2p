# V0.9 Acceptance — Secure UDP Connectivity Check

## Implementation checklist

- [x] New branch from V0.8 preserves committed history and does not overwrite main V0.7.
- [x] Windows explicit opt-in to test UDP connectivity (default off, changed only when host stopped).
- [x] Android manual UDP punch button only on a current authorized VPS WSS session.
- [x] AES-GCM-encrypted candidate exchange over existing relay WebSocket, not plaintext HTTP.
- [x] Both sides use the SAME bound UDP socket for STUN and encrypted peer handshake.
- [x] Versioned signal JSON, strict IPv4 and UDP port validation; no DNS hostnames in candidate payload.
- [x] Per-side randomized 16-byte challenge with AES-GCM authenticated type-11 HELLO/type-12 ACK.
- [x] 12-second timeout plus 1-second ACK response grace period and cancellation on stop/disconnect.
- [x] Video/remote controls always remain on existing VPS WebSocket when probe succeeds or fails.
- [x] Rust/Kotlin encrypted packet integrity and candidate-policy tests.
- [x] Go websocket relay integration test for opaque encrypted signal forwarding.
- [x] CI workflow prepares Windows EXE, Android APK, SHA-256 checksums and Go/STUN Docker tests.

## GitHub Actions acceptance (DO NOT mark successful before runner jobs execute)

- [ ] Windows cargo test and cargo build --release pass on Windows runner.
- [ ] Android testDebugUnitTest and assembleDebug pass.
- [ ] Go go test -race ./... passes, including bidirectional encrypted signaling test.
- [ ] Docker Compose STUN override validation and relay image build pass.
- [ ] ZIP / APK / SHA-256 artifacts are uploaded from the same Git SHA.
- [ ] Repository secrets are not exposed, and all jobs have real step logs.
- [ ] If zero-step failure repeats, keep PR in draft and direct owner to existing Issue #9.

## Required real-device network acceptance (cannot be replaced by CI)

- [ ] VPS WSS relay / Caddy HTTPS works and UDP 3478 optional STUN is enabled safely.
- [ ] Windows default checkbox OFF: Android request does not create a UDP probe.
- [ ] Windows checkbox ON + Android tap: the two peers exchange encrypted candidates.
- [ ] A valid LAN or permissive NAT mapping produces authenticated UDP ACK on both ends.
- [ ] Wrong session key or altered kind/nonce cannot produce false UDP success.
- [ ] Strictly bounded 12-second failure on CGNAT/symmetric NAT or UDP-blocked networks.
- [ ] Android on separate Wi-Fi / 5G correctly reports success or fallback without claiming media P2P.
- [ ] No screen, mouse, keyboard, clipboard, credentials or bearer token is sent over UDP.
- [ ] Stopping the Windows app or Android session closes UDP sockets and invalidates peer state.
- [ ] Run 8-hour screen/control stability test over the independent VPS session.

## What V0.9 does NOT deliver

- ICE-compliant candidate checks, authenticated public key identities, TURN allocation or QUIC P2P video/input transport.
- Real GPU hardware encoder or guaranteed 1080p30/sub-200ms remote viewing.
- Commercial code signing, production server deployment or manual WAN testing.

**Release gate:** V0.9 remains a feature PR until all cloud builds pass; main stays on its last confirmed stable-testing version.

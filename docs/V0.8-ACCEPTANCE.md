# P2P Remote V0.8 acceptance

## Code complete (must pass CI before claiming binaries)

- [x] Go optional IPv4 STUN UDP 3478 server with Binding request validation, XOR-MAPPED-ADDRESS response and no client IP logging.
- [x] Docker Compose optional override file for UDP 3478, off by default.
- [x] Windows Rust user-triggered STUN probe with transaction ID validation and external mapping/UDP RTT reporting.
- [x] Android Kotlin nonblocking user-triggered STUN probe with exact 96-bit transaction ID validation.
- [x] Android encrypted ping every ~5 s; Windows sends authenticated PONG with identical 8-byte nonce via LAN/VPS.
- [x] Compose Android UI displays live signaling RTT (not video latency) plus STUN probe status.
- [x] Rust/Android unit tests for malformed STUN responses; Go localhost UDP roundtrip test.
- [x] All V0.7 LAN direct, VPS fallback, input permissions, JPEG/H.264 and trusted pairing paths retained.

## GitHub cloud CI gates

- [ ] Windows Rust cargo test and Release EXE compile succeed.
- [ ] Go STUN loopback and security/race tests pass, Docker image builds.
- [ ] Optional STUN Docker Compose override `docker compose config` passes.
- [ ] Android StunProbeTest and other JVM tests pass; debug APK builds.
- [ ] Windows and Android artifacts and SHA256 exist from the same commit.
- [ ] No secrets embedded or exposed in CI logs.

## Manual tests on real owner devices (not possible from CI)

- [ ] VPS WSS relay deployed and working, with valid TLS certificate and private relay token.
- [ ] Enable optional `compose.stun.yml`; confirm UDP 3478 allowed by VPS provider firewall.
- [ ] Windows button reveals observed UDP address/port, or explicit failure without crash.
- [ ] Android button on Wi-Fi and 5G reports different observed address/port or a valid failure.
- [ ] STUN disabled: diagnostics fail safely; the existing WSS relay still works.
- [ ] Android E2E signaling RTT appears on LAN and on VPS and disappears on disconnect.
- [ ] Wrong AES session key cannot produce valid PONG or send accepted control commands.
- [ ] Mobile reconnect and Wi-Fi↔5G transitions do not leave stale RTT status.
- [ ] 8-hour capture and input stability verified with memory, FPS, bandwidth and latency logs.
- [ ] Windows service startup and UAC/lock screen restrictions remain enforced.

## Not delivered

- Cross-Internet ICE/STUN hole punching, UDP peer candidate negotiation, relayless streaming across NAT, TURN, secure UDP packet fragmentation, IP address discovery from arbitrary unknown devices, or verified P2P success rates.
- GPU H.264 encoding and production security/signing audits.

The STUN Binding result comes from a temporary probe socket and is **never** a live reusable candidate. It must not be shown as 'P2P connected'.

# V0.9 CI blocker — 2026-11-12

## Directly observed

- V0.9 push run: https://github.com/chengzi1994999/p2p/actions/runs/43197915289
- V0.9 pull-request run: https://github.com/chengzi1994999/p2p/actions/runs/43198036569
- Both runs ended in failure for ALL three jobs: Windows Rust, Android Compose, Linux Go.
- GitHub Actions job metadata shows **zero registered steps** for all six jobs.
- No Rust, Kotlin or Go test commands were executed on these runs; no V0.9 Windows/Android build artifacts exist.
- Same failure mode was previously documented for V0.8 in Issue #9, while the earlier V0.7 main CI had completed successfully.

These facts are more consistent with GitHub-hosted runner provisioning / usage / billing / repository policy than a source compilation error, but **the specific cause remains unverified**.

## Safe release decision

- Maintain this feature as a draft PR based on the V0.8 branch.
- Keep `main` at the existing V0.7 merge commit until V0.8/V0.9 build and manual testing gates pass.
- Do not provide fake artifact IDs or assert successful Windows/Android compilation.

## Repository owner checks

1. GitHub user settings → Billing & licensing → Usage / Budgets; check Actions minutes, budget or payment restrictions.
2. Repository → Settings → Actions → General; verify workflow permissions and hosted runner use.
3. Open one of the failed run pages; inspect the top-level red error banner (allocation/usage/policy details).
4. If settings allow Actions, contact GitHub Support with the exact run IDs and zero-step failures; refer to Issue #9.
5. After resolving the blocker, re-run the PR checks. Verify Rust/Android/Go results, SHA-256 hashes, and use real VPS + Windows + Android devices for connectivity testing.

## What the submitted code does not prove

Secure UDP candidate exchange and a 12-second AES-GCM connectivity test are implemented in source but not yet compiled or proven on physical devices. ICE/QUIC-based remote desktop traffic does not exist in V0.9. Real end-to-end WAN results are unknown.

# P2P Remote V0.11 — Windows Viewer and Chinese font

## Development baseline
- Base: `feature/v0.10-udp-jpeg-preview`
- Branch: `feature/v0.11-windows-viewer-font`
- Relay: `wss://p2p.aikissgo.com`
- This is a **test build**, not a released/validated PC-to-PC remote control product.

## Implemented in source
- [x] Set Windows Iced default font to Microsoft YaHei UI for Chinese text on Windows.
- [x] Change Windows and Android default WSS relay URL to `p2p.aikissgo.com`.
- [x] Add Windows Viewer WSS `role=viewer`, reusing AES-256-GCM, session room derivation and Relay bearer authentication.
- [x] Display authenticated JPEG desktop frames; send encrypted mouse/scroll/text/monitor/clipboard-get commands.
- [x] Explicit Viewer Connect/Disconnect controls; no automatic Viewer startup.
- [x] Separate Viewer session key field; never put credentials in relay URLs.
- [x] Add V0.11 self-hosted Windows EXE and Android APK CI workflow.

## Restrictions in this initial implementation
- Viewer is currently **WSS JPEG only**, not H.264 decoding or direct LAN/UDP Viewer transport. Disable H.264 encoding on the controlled PC.
- Viewer controls reuse current Host permission gates; owner must allow mouse/keyboard/clipboard.
- There is no standalone full-screen viewer, continuous reconnect, file transfer, or remote keyboard scan-code forwarding.
- Pointer mapping is based on a 16:9 display surface. Verify coordinates on other monitor aspect ratios.
- Windows Font selection still requires real-world Windows 10/11 visual verification, including machines without YaHei UI installed.
- Server deployment and DNS/TLS status have not been verified. No production deployment was requested.
- V0.10 UDP JPEG remains experimental and Android-only.
- The screenshot in the chat exposed a local session key; rotate it before real-world use.

## Manual test
1. On PC A open Windows Host. Set WSS URL, Relay Token and session key. Keep H.264 OFF, enable remote service, explicitly allow remote input if desired.
2. On PC B open same EXE. Enter the same WSS domain/token; in Windows Viewer enter PC A's session key.
3. Click Connect, verify JPEG frames and test mouse, scrolling, text and monitor selection.
4. Deny input on PC A and verify that commands have no effect. Test wrong session key, wrong token and disconnect.
5. On Android, verify connection using matching settings and unchanged original behavior.

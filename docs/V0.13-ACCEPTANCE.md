# P2P Remote V0.13 — Fullscreen, Keyboard and Multi-monitor Acceptance

## Branch and deployment boundary

Branch: `feature/v0.13-remote-controls`, forked from the V0.12.1 successfully built test version. Uses the existing `wss://p2ptest.aikissgo.com` default relay. **No production or staging server deployment is requested by this branch.** This is an integration-testing build, not V1.0 or a validated production release.

## In-source features (must pass CI and real-device testing)

### Windows (Rust / Iced 0.13.1)

- Fullscreen toggle on the Viewer page using Iced's actual OS window mode. Return control is always visible. The remote canvas size follows window resize events, with the same helper used by pointer coordinate mapping. This is not merely hiding the sidebar.
- Existing non-fullscreen compact/standard/large video presets remain.
- Direct numbered monitor selection for the first six displays; previous/next selection supports all reported 1–16 displays.
- Remote keyboard toolbar: arrow navigation, Home, End, Page Up/Down, Enter, Backspace, Tab, Escape, Delete, Space.
- Explicit Ctrl+A/C/V/X/Z/Y editing shortcuts. Windows Host continues to require the owner to enable remote input and accepts only the allowlisted names, not arbitrary scan codes or injected shell commands.
- JPEG-over-WSS viewer limitation remains. The controlled PC must disable H.264 encoding for Windows Viewer sessions.

### Android (Kotlin / Compose)

- Direct monitor picker with horizontally scrollable buttons when more than one screen is reported.
- Touch toolbar for arrow navigation, editing/navigation keys and common text shortcuts, using the same strict keyboard action allowlist as the Host.
- Release remote left mouse button on gesture cancellation and tab change to reduce stuck drags. Right-click requires a previously valid touch in the image region.
- Existing security gates, session keys, settings and optional Android H.264/UDP features are retained.

## Manual physical acceptance (not established by CI)

1. PC A (Windows Host) starts WSS on `p2ptest.aikissgo.com`; PC B (Windows Viewer) connects with an explicitly authorized token and matching session secret. With no input permission, remote keyboard/mouse actions do nothing.
2. Enter/leave fullscreen at 1366×768, 1920×1080 and at least one 125–200% DPI setting. The window genuinely enters OS fullscreen and can always return without a stuck cursor/button.
3. Verify remote click positions at image center and corners for a 16:9 monitor and a 4:3 monitor (black-bar clicks ignored).
4. Test explicit monitor selection and previous/next on a host with at least two physical or attached displays.
5. Test arrows, Home/End, Page Up/Down, Enter, Backspace, Ctrl+A/C/V/X/Z/Y in a disposable text editor. Check keyboard layout differences and Windows accessibility permissions.
6. Android → Windows: verify the new keyboard toolbars, direct monitor selection, switching to another tab during touch dragging and Wi-Fi ↔ cellular reconnection.
7. With wrong access token/secret, permission revoked, or host stopped, no remote inputs are accepted.
8. Record FPS, RTT, CPU/memory and connection stability during a 30-minute session and at least ten reconnects.

## Known deferred scope

- Full physical-keyboard scan-code forwarding, IME/complex hotkeys, remote secure/UAC desktop, file transfer, automatic account/device discovery, GPU H.264 for Windows Viewer, adaptive scaling based on per-monitor DPI, reliable ICE/TURN NAT traversal, audio, signed production installers and automatic updates.
- User must complete the hardware/visual test phase before V0.13 is called "accepted".

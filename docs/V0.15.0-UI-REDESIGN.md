# P2P Remote V0.15.0 — Windows + Android UI Redesign

## Product objective

Replace the V0.14 engineering-style presentation with a consistent, production-oriented interface across Windows Host and Android Viewer. Keep the current Rust/Iced and Kotlin/Jetpack Compose stacks. This is a visual and interaction-architecture update, not a protocol rewrite.

## Visual system

- Dark navy workspace with layered slate panels.
- Mint/teal primary action and connection accent; warm amber reserved for secondary attention.
- High-contrast text, clearer hierarchy, larger touch targets, consistent rounded cards and spacing.
- Same brand/version treatment and connection-state semantics on both platforms.
- Avoid exposing internal protocol, relay, STUN and debug terminology in primary user flows; keep diagnostics in advanced settings.

## Windows Host

### Implemented in this branch
- Switch from Tokyo Night to a neutral dark theme.
- Update application title and visible brand to V0.15.
- Increase default window size to 1280×820.
- Refresh the left navigation rail, brand accent and workspace spacing.
- Replace flat grey cards with layered navy cards, softer borders and larger radii.
- Improve heading contrast, size and subtitle readability.

### UI acceptance
- Sidebar remains usable at 1280×820 and 1366×768.
- Home clearly prioritizes device number, six-digit one-time code, expiry countdown, copy actions and Start/Stop sharing.
- Pending pairing approval is visually distinct and requires explicit Allow/Deny.
- Remote screen retains fullscreen, monitor selection, zoom, pointer, keyboard and clipboard controls.
- Settings and Network remain separate; advanced diagnostics do not crowd the home page.
- Tray behavior and close-to-tray behavior are unchanged.

## Android Viewer

### Implemented in this branch
- Establish shared V0.15 navy/mint palette and high-contrast Material 3 color scheme.
- Refresh the brand header and online/offline state badge.
- Simplify bottom navigation labels and strengthen selected-state typography.
- Convert content panels to elevated, bordered surfaces with consistent 20dp corners and spacing.

### UI acceptance
- Device page clearly distinguishes saved trusted PC from first-time numeric pairing.
- Device number and six-digit code fields remain numeric and constrained to 9 and 6 digits.
- Pairing progress, cancellation, approval wait, timeout and rejection remain visible.
- Remote screen keeps gesture-based pointer input, pinch zoom, pan, fullscreen expansion, monitor selection and H.264 playback.
- Settings/clipboard controls remain explicit and permission-aware.
- Verify 360dp, 393dp and 430dp widths; no clipped buttons or horizontal overflow.
- Verify Android system bars, keyboard insets, portrait and landscape layouts.

## Compatibility and safety constraints

- No changes to relay API routes, message schema, cryptographic derivation, session encryption, pairing proof, or device identity storage.
- Do not weaken host approval, input permission, clipboard permission, or trusted-device consent.
- Do not log pairing codes, proofs, private seeds or session secrets.
- Preserve Windows tray, per-user install, portable data isolation and DPAPI behavior.
- Keep Android Keystore storage and user-initiated trusted-device save behavior.
- Do not deploy or alter the production Relay/server.

## Build and verification

- Windows: cargo fmt --check, cargo test, cargo build --release, PE GUI subsystem check, NSIS installer, portable ZIP and SHA-256.
- Android: :app:testDebugUnitTest and :app:assembleDebug.
- Relay: go test -race -count=1 ./... and go vet ./....
- Compare screenshots at the acceptance resolutions.
- Install the Windows installer and portable package on a clean Windows user profile.
- Install APK on a physical Android device and perform real pairing/remote desktop checks.

## Release gate

CI success is necessary but not sufficient. Do not call V0.15 production-ready until screenshots, Windows installation/portable startup, physical Android layout, numeric pairing, approval/denial, remote input, reconnect and tray behavior pass manual acceptance.

# P2P Remote V0.19 — Flutter + native remote engines

V0.19 continues the approved Flutter + Rust + Go architecture and connects the Android Flutter UI to the existing Kotlin remote-control stack.

## Windows

- Flutter calls the existing Rust Host/Viewer core through the C ABI.
- Windows native Host and Viewer use the existing pairing, AES-GCM framing, DPAPI credential vault, Win32 input injection, monitor selection and clipboard authorization.
- The Windows runner adds a notification-area icon. Closing the main window hides it; clicking the tray icon restores it; the tray menu provides an explicit Exit command.
- The Windows release package contains the complete Flutter runtime, the Rust DLL, and an NSIS per-user installer.
- Uninstall removes application files and shortcuts but intentionally leaves per-user DPAPI credentials intact.

## Android

- Flutter calls `AndroidRemoteEngine` through MethodChannel and EventChannel.
- The bridge reuses the existing Kotlin numeric pairing, signed pairing-window verification, X25519/HKDF session derivation, AES-256-GCM packets, WSS Relay, reconnect policy, UDP probing, monitor metadata, input commands and clipboard protocol.
- JPEG frames are sent to Flutter as bounded byte events.
- H.264 frames are decoded by Android MediaCodec into a Flutter SurfaceTexture and displayed using Flutter's `Texture` widget.
- Relay URL and access token are encrypted with an Android Keystore AES-GCM key; the token is never returned to Dart.
- Android is the Viewer/control side in this phase. Windows remains the Host/desktop-sharing side.

## Build and verification

The V0.19 workflow builds both targets:

- Windows: Rust core tests, Rust release DLL, Flutter analyze/tests, Flutter Windows release, tray integration, complete ZIP and NSIS installer.
- Android: Flutter Android runner generation, Kotlin native bridge source integration, Flutter analyze/tests and release APK.

The Android platform runner is generated by Flutter CLI and prepared by `scripts/prepare-flutter-android.py`. The Windows tray runner is patched by `scripts/prepare-flutter-windows-tray.ps1`.

## Not yet complete

- Android as a Host that shares its own screen.
- Multi-device encrypted device library migration.
- Windows-to-Windows and Android-to-Windows physical-device acceptance on the user's actual machines.
- Signed production installer and automatic update channel.
- Full ICE-based NAT traversal; the current WSS Relay and existing UDP probe remain unchanged.

## Security and deployment

- No Go Relay API, WSS room/role derivation, AES-GCM framing, pairing signatures, X25519/HKDF domains or approval semantics are changed.
- Android Relay credentials are stored using Android Keystore-backed AES-GCM.
- Windows long-term credentials remain protected by DPAPI for the current Windows user.
- Remote input and clipboard permissions remain controlled by the Windows Host user and default to disabled.
- No production or test Relay deployment is performed by this branch.
